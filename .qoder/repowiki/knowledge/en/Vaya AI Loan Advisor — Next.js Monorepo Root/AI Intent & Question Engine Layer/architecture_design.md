The layer is organized around a single `LLMProvider` interface in `provider.ts`, implemented by an OpenAI-compatible client that switches between DashScope (Qwen) and DeepSeek based on the `LLM_PROVIDER` env var. All AI consumers — `intent.ts` (classify + profile merge), `questionEngine.ts` (adaptive follow-up questions from `@/data/intakeQuestions`), and the RAG subpackage (`rag/embed.ts`, `rag/retrieve.ts`, `rag/store.ts`) — depend only on this interface, keeping prompt logic isolated in `prompts/*`. The flow is: `extractAndClassify` calls `llm.extractIntent` with a system prompt and a function tool to pull a loan profile, then `classifyIntent` decides NUMERIC/POLICY/MIXED; for numeric intents the question engine fills missing required fields, while policy intents route through `answerPolicyQuery` using RAG context chunks.
