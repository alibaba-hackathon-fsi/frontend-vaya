The module is a flat collection of pure-function utilities organized around a single shared type contract in `types.ts` (Bps, LoanProduct, InstallmentRow, HouseholdInput, SurvivabilityReport, etc.). `pipeline.ts` is the entry point `runCalculation(profile)` that chains deterministic stages: `filterEligible` → `calcMonthlyPayment` → `calcDTI` → `scoreRisk` → `rankMCDA`, with data sourced from bundled `@/data/loanPackages` and `@/data/eligibilityRules`. The survivability subsystem composes lower-level modules — `amortization.ts` (ANNUITY/EQUAL_PRINCIPAL schedules), `rate-schedule.ts`, `grace-period.ts`, `cliff-detector.ts`, `household.ts`, `shocks.ts`, `improvements.ts`, and `scenarios.ts` (four base-rate scenarios) — into `survivability.ts` which builds a 16-cell grid (4 rate scenarios × 4 shocks) and derives tier/warnings/improvements. Each file exports a single focused function or constant set with no side effects, no I/O, and no LLM calls, making the whole layer testable and backend-portable.
